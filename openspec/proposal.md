## Why

Third-party integrators calling hush-hush today either hand-roll HTTP requests against `api/openapi.yaml` or reach for `internal/client`, which is deliberately unexported and not meant to leave the repo. hush-hush's own issue [#74](https://github.com/alrayyes/hush-hush/issues/74) asks for an official, separately-versioned Go SDK so integrators get typed methods instead.

## What Changes

- New public repo `github.com/alrayyes/hush-hush-go` providing a typed Go client for hush-hush's v1 API surface (create/get/update/delete, audit-log query).
- Request/response types and route bindings generated from hush-hush's `api/openapi.yaml` via `oapi-codegen`; generated files carry a `// Code generated by oapi-codegen; DO NOT EDIT.` header, checked in CI.
- Hand-written client layer on top of the generated code: constructor accepting bearer token (with an environment-variable fallback), base URL, timeout and max-retry config; exponential backoff with jitter on network failures and 5xx/429 only (honoring `Retry-After` when present, never retrying other 4xx); typed errors carrying HTTP status, request ID, and parsed error body; a typed audit-log query method (hush-hush's `/audit-log` has no pagination parameters, confirmed against the actual spec, so this doesn't invent an iterator over one).
- The spec is pulled into the repo pinned to an exact hush-hush commit/tag (submodule or fetch step), never copy-pasted; the pinned commit is recorded in-repo, not only in a commit message.
- Versioning: semver bump decided by diffing the spec (`openapi-diff`) against the version last generated from, not by Conventional Commits on this repo.
- CI regenerates on a schedule/webhook from hush-hush's spec and opens a PR — never regenerates and pushes directly. Full auto-merge applies to this repo's PRs for this session (scaffolding and regeneration alike, per an explicit repeated grant), with the spec-diff's additive/breaking classification still surfaced on every PR for visibility even though it doesn't gate merge.
- Testing: unit tests cover only the hand-written layer (retry, auth, pagination, error mapping) against a fake transport; contract tests run the client against a Prism mock server generated from the same spec; a Pact consumer contract records the client's real interactions for provider verification against hush-hush itself (verification step lives in hush-hush's own CI — external dependency, not built by this change).
- Docs: godoc comments on all exported identifiers (published automatically via pkg.go.dev); a hand-written README quickstart covering install, auth setup, and one real call.
- Targets Go 1.26+ (the two most recent Go majors receive fixes; older ones don't).

## Capabilities

### New Capabilities

- `sdk-go`: the Go SDK's client behavior — constructing a client, calling typed methods against hush-hush's v1 API surface, error/retry/pagination handling, and staying in sync with the pinned spec version.

### Modified Capabilities

None — this introduces a new repo and does not change hush-hush's own API behavior.

## Impact

- New repo: `github.com/alrayyes/hush-hush-go`, public, own CI/release pipeline.
- hush-hush's own README gets a link added once the SDK repo exists (an edit to that repo, made by whoever owns it, not by this change).
- No changes to hush-hush's server code. Wiring Pact provider verification into hush-hush's CI is a request to that repo's owner, tracked as a dependency of this change rather than performed by it.
- Depends on hush-hush's `api/openapi.yaml` remaining the spec-first source of truth; does not modify it.
