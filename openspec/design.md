## Context

See proposal.md for motivation. Relevant constraints: hush-hush's `api/openapi.yaml` is the spec-first source of truth, linted via Redocly but with no mechanical check that server behavior matches it; there's no existing API-version concept separate from hush-hush's own release-please semver; auth is a single static bearer token required on write paths only, plus an optional unverified `X-Caller` header; nothing generated or hand-written exists yet for this SDK.

## Goals / Non-Goals

**Goals:**
- A deterministic, mechanically regenerable client — running the pipeline twice against the same spec commit produces the same output.
- Idiomatic Go: `context.Context` as the first parameter, `(T, error)` returns, no panics on API errors.
- An unambiguous generated/hand-written boundary that survives regeneration.
- A regeneration pipeline where a breaking spec change can't slip through as a "small diff."

**Non-Goals:**
- OAuth2 support — hush-hush only has a static bearer token.
- A unified cross-language docs site (see [[hush-hush-sdk-decisions]] equivalent reasoning: per-language native docs only).
- Any change to hush-hush's server or its spec.
- Implementing Pact provider verification inside hush-hush's own CI — that's a request to that repo's owner, tracked as an external dependency of this change.

## Decisions

**Generator: `oapi-codegen`, not `openapi-generator`'s generic Go template or a hosted platform (Speakeasy/Fern/Stainless).** `oapi-codegen` produces idiomatic `net/http`-based Go that reads like hand-written code and is the de facto standard in the Go ecosystem; `openapi-generator`'s Go templates read more like a transliterated Java client. Hosted platforms were rejected project-wide in favor of free OSS tooling.

**Generated/hand-written boundary via header comment, not a custom-code region.** `oapi-codegen` has no native "custom region" concept (unlike Speakeasy/Fern/Stainless), so the boundary is a single generated file (`client.gen.go`) carrying `// Code generated by oapi-codegen; DO NOT EDIT.`, with a CI check that fails if that file's diff isn't purely mechanical regeneration output. All hand-written code — client construction, retry, auth, error mapping, pagination — lives in separate files that wrap the generated `ClientInterface`.

**Spec pinning via git submodule, not a copy or a separate version file.** The submodule's pinned commit *is* the version record — no redundant `SPEC_VERSION` file needed. The generated file's header comment additionally states the pinned commit for human readability without another file to keep in sync.

**Versioning via spec diff.** `openapi-diff` compares the current pinned commit against the one the last release was generated from and classifies the change as additive/non-breaking (minor/patch bump) or breaking (major bump) — decided from the spec diff, not from Conventional Commits or the shape of the generated-code diff.

**Merge policy: full auto-merge for this session, scaffolding and all regeneration PRs alike.** Ryan gave this session an explicit, repeated auto-merge grant, including after being shown the specific risk that a breaking spec change can produce a small, green-CI-passing generated-code diff — see Risks below. The `openapi-diff` classification from the decision above still runs and is still visible on every PR; it drives the version bump and gives a maintainer a fast way to spot a breaking regeneration after the fact, even though it no longer gates merge.

**Auth: bearer token in the constructor with an env var fallback (`HUSH_HUSH_API_KEY`); `X-Caller` as a per-request functional option, not client-level config.** The server only requires the bearer token on write paths, and get/audit-log calls work without it — one client instance should still serve both cases. `X-Caller` identifies the calling *program* per call, which is a per-request concern, not a client-wide one.

**Retry: network failures, 5xx, and 429 only; exponential backoff with jitter; honor `Retry-After` when present.** Never retry other 4xx — retrying a validation error doesn't make it stop being wrong.

**Errors: a typed `APIError` carrying status, an optional request-ID field, and the parsed error body.** The request-ID field is populated when the response carries a documented request-ID header and left empty otherwise, so the design doesn't depend on confirming that header exists before implementation starts.

## Risks / Trade-offs

- [`oapi-codegen` has no enforced custom-code region, so a hand-edit could land inside the generated file] → CI check on the generated file's diff shape catches it before merge.
- [Git submodule adds friction for a casual `git clone`] → CI handles submodule init automatically; documented as a one-line setup step in the README.
- [hush-hush has no real API-version concept, so nothing on the server side confirms what "v1" actually locks to] → the SDK's own version and pinned spec commit are the source of truth for parity, independent of hush-hush's release version.
- [Pact provider verification depends on hush-hush's CI adopting the new consumer, which hasn't happened yet] → until it does, spec-vs-server semantic drift isn't mechanically caught — same gap that exists today, not made worse by this change.
- [A breaking spec change can auto-merge as a small, green-CI-passing generated-code diff, since full auto-merge applies to all regeneration PRs] → accepted risk, per Ryan's explicit repeated auto-merge grant for this session. The `openapi-diff` classification still runs and is visible on every PR after the fact, so a maintainer reviewing history can spot a breaking merge even though nothing blocked it.

## Open Questions

- Whether hush-hush's responses actually carry a request-ID header — if not, `APIError.RequestID` simply stays empty; doesn't change the error type's shape.

Resolved during implementation (2026-08-29): the audit-log query has no pagination — checked directly against hush-hush's `api/openapi.yaml` (pulled via the pinned submodule). `/audit-log` takes only `object_id`/`caller`/`from`/`to` filters and returns a flat array. The SDK exposes a single typed query method returning a slice, not an iterator — see the corrected "Audit log query" requirement in specs/sdk-go/spec.md. The spec also documents a sixth operation, `GET /objects/{id}/used-by`, missed in the original proposal; it's included as a typed method alongside create/get/update/delete/audit-log.
